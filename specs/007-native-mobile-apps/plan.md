# Implementation Plan: Native iOS and Android Apps

**Branch**: `007-native-mobile-apps` (spec directory; the working git branch is `main`)
| **Date**: 2026-10-12 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/007-native-mobile-apps/spec.md`

## Summary

Wrap the existing React front end in a Capacitor shell for iOS and Android, bundled into the app and
talking to the existing FastAPI service over HTTPS. No business logic moves to the device
(constitution XXXIII).

```
[ iOS / Android shell (Capacitor) ] → [ same React UI, bundled ] → [ existing FastAPI ] → [ Supabase Postgres ]
```

Four steps, in the order the supplied plan gives them, with account deletion added as its own
track because it blocks the App Store (spec FR-012):

1. **Harden mobile web** — the floor every app build stands on (XXXV), proven in real phone
   browsers before any shell exists.
2. **Capacitor project** — `frontend/` gains `ios/` and `android/`; `webDir` is the production
   build; native-only behaviour (secure token storage, app start route, external links) sits behind
   one small platform module.
3. **Native polish** — icons, splash, status bar, safe areas, HTTPS only.
4. **Store readiness** — privacy policy update, screenshots, account deletion, TestFlight and Play
   internal testing, real-device QA on both platforms (XXXIV).

Two places where this plan deliberately departs from the supplied brief, both explained in
research.md: the dispatch submit stays **in document flow rather than sticky** (R2), and account
deletion is **required, not conditional** (R8).

## Technical Context

**Language/Version**: TypeScript 5.6 (frontend + shell config), Python 3.12 (backend changes),
Swift/Kotlin only as generated by Capacitor (no hand-written native code planned)

**Primary Dependencies**: Capacitor (current major) with `@capacitor/ios`, `@capacitor/android`,
`@capacitor/app`, `@capacitor/splash-screen`, `@capacitor/status-bar`, `@capacitor/browser`, and a
Keychain/Keystore secure-storage plugin (R4); `@capacitor/assets` for icon/splash generation

**Storage**: tokens in platform secure storage on device; no other on-device data. Server storage
unchanged except account-deletion fields (data-model.md)

**Testing**: existing pytest/Vitest/Playwright, plus unit tests for the platform module, backend
tests for account deletion and purge, and recorded real-device QA (iPhone + Android)

**Target Platform**: Android 8.0+ (API 26), iOS 15+ (iPhone; iPad runs the same build)

**Project Type**: web application + mobile shell — `backend/`, `frontend/` (with `frontend/ios`,
`frontend/android`)

**Performance Goals**: two-item dispatch recorded in < 60 s from app open on a physical phone
(SC-001); app opens to a usable screen without fetching its UI over the network

**Constraints**: HTTPS only, cleartext disabled; no offline queue (XXXVII); no purchase/upgrade UI
in the app (IX, store payment rules); same features on both platforms (XXXIV)

**Scale/Scope**: 6 user stories, 13 FRs. One new platform module and a small set of web changes;
backend gains account deletion, a purge job, and CORS origins for the app
